# Person 3 Decoder Contract

## Boundary

The decoder is an inference component. Its inputs are GPS observations,
directed graph artifacts, candidate arc IDs, and calibrated probabilities. It
does not accept route labels or reference geometry.

Offline scripts may separately load `reference_labels.csv` to compare
classifier-only and HMM/Viterbi predictions. This boundary prevents evaluator
labels from entering the prediction pipeline or the UI.

## Required validations

1. GPS indices are unique and ordered.
2. Candidate rows belong to one requested trip.
3. Candidate GPS indices exist.
4. Candidate arc IDs exist in the directed graph.
5. Nodes use projected metre coordinates.
6. Model and decoder manifests use compatible schema versions.

## Person 2 model-artifact contract

Before Person 4 may load an emission model, Person 2's saved artifact must
contain all of the following fields:

```text
model                 fitted object implementing predict_proba
scaler                fitted scaler, or null when needs_scaling is false
needs_scaling         boolean
feature_cols          frozen, ordered list of feature names
feature_schema_version  e.g. pathsnap-candidate-v1
model_version         immutable artifact/version identifier
calibration_method    e.g. isotonic or sigmoid
```

Person 2 must also generate out-of-fold calibrated candidate scores for the
80 train trips. Person 3 uses these for decoder tuning. A raw `predict_proba`
artifact with no calibration metadata is rejected in production mode.

## Person 1 inference-artifact contract

Person 1 must export label-free frames for every inference trip:

```text
gps:        pt_idx,timestamp,x_m,y_m,lon,lat,usable
nodes:      x_m,y_m,lon,lat
arcs:       from_node_id,to_node_id
candidates: trip_id,pt_idx,cand_arc_id,<frozen feature columns>,candidate_miss
```

Candidate/feature generation must run when the `.route` file is absent. Route
labels may be generated by a separate training/evaluation-only alignment step.

## API-safe result fields

`trip_id`, predicted point-level arc IDs, compact/expanded predicted routes,
warnings, decoder version, and inference time are safe result fields. Reference
arc IDs, reference-route geometry, and per-point correctness labels are not.

## Warning codes

- `EMPTY_CANDIDATE_SET`
- `UNUSABLE_GPS_POINT`
- `LARGE_GPS_GAP`
- `NON_INCREASING_TIMESTAMP`
- `DUPLICATE_CANDIDATE_DEDUPLICATED`
- `INVALID_PROBABILITY_CLIPPED`
- `ALL_PREDECESSORS_DISCONNECTED`
- `DISPLAY_ROUTE_DISCONNECTED`

Person 4 should expose a safe summary of these codes in API logs and UI status,
not raw tracebacks.
